# Credentials checklist — everything the OpenShift + Lightwell + RHTAS demo needs

## Note: Podman, not Docker

Use **Podman** or Docker locally — either works with the oc commands below. That is fine everywhere here:

- `oc create secret docker-registry` is an **oc subcommand**, not the docker CLI. "docker-registry"
  is just the Kubernetes secret *type* (`dockerconfigjson`) — it works with Podman or no container
  tool at all. Every such command below runs as-is.
- To **verify** registry access locally, use Podman:
  ```bash
  podman login registry.redhat.io --username 'NNNNNNN|name' --password 'TOKEN'
  podman pull registry.redhat.io/rhtas/cosign-rhel9:1.3.5
  ```
  (Apple Silicon Macs: these Red Hat images are amd64; expect a "platform" warning locally.
   Irrelevant on the cluster, whose nodes are amd64.)


Gather these before running. **Use tokens/service accounts, never account passwords.**
Nothing here goes into a file you commit — create secrets on the cluster with `oc`.

## 1. Red Hat Lightwell — pull the remediated dependencies
For the Maven build to resolve `…redhat-NNNNN` jars from packages.redhat.com.

| Item | Where to get it | Used as |
|---|---|---|
| **Service account username** — `orgID\|service-account-name` | console.redhat.com → your service account | Maven `settings.xml` `<username>` + `RHLN_USER` |
| **Service account token** | same page (shown once) | Maven `settings.xml` `<password>` + `RHLN_TOKEN` |

Cluster secret:
```bash
oc create secret generic lightwell-maven-settings \
  --from-file=settings.xml=/tmp/settings.xml -n upgrade-delta-demo
```
Local scripts (`lightwell-report.sh`, `fetch-lightwell-app-jars.sh`):
```bash
export RHLN_USER='orgID|service-account-name'
export RHLN_TOKEN='...'
```

## 2. registry.redhat.io — pull the RHTAS cosign image + operator images
For the signing tasks (`rhtas/cosign-rhel9`) and the RHTAS operator/stack images.

| Item | Where to get it | Used as |
|---|---|---|
| **Registry service account username** — `NNNNNNN\|name` | registry.redhat.io → Service Accounts (or access.redhat.com/terms-based-registry) | docker-registry secret `--docker-username` |
| **Registry service account token** | same page | docker-registry secret `--docker-password` |

Cluster secret + link to the pipeline SA:
```bash
oc create secret docker-registry redhat-registry \
  --docker-server=registry.redhat.io \
  --docker-username='NNNNNNN|name' \
  --docker-password='TOKEN' -n upgrade-delta-demo
oc secrets link pipeline redhat-registry --for=pull -n upgrade-delta-demo
```
NOTE: this is a **registry** service account (registry.redhat.io), which is *different*
from the **console** service account in #1 (console.redhat.com). You need both.

## 3. GitHub — PR trigger via Pipelines-as-Code
For PaC to receive PR events and report status back. Created by the bootstrap, not by hand.

| Item | Where to get it | Used as |
|---|---|---|
| **GitHub account with admin on the repo** | your account (anurag-saran) | `opc pac bootstrap` (creates a GitHub App) |
| GitHub App private key + webhook secret | auto-generated by `opc pac bootstrap` | stored on-cluster automatically |

```bash
opc pac bootstrap        # opens browser, creates + installs the GitHub App
```
You do NOT paste a GitHub token manually — the bootstrap handles the App credentials.
(If you prefer a token-based webhook instead of a GitHub App, that path needs a
Personal Access Token with `repo` scope — but the App flow is recommended.)

## 4. OpenShift cluster — admin access
For installing operators and creating the namespace/secrets.

| Item | Where to get it | Used as |
|---|---|---|
| **cluster-admin kubeconfig / login** | your cluster (api.EXAMPLE.com) | `oc login` |

## 5. Sigstore OIDC token — keyless signing identity
Keyless cosign needs an identity token; **this is not a static secret you fetch** — it's
minted at run time. Provide it one of two ways (see `integration/tekton/rhtas/README.md`):
- **Projected ServiceAccount token** (audience `sigstore`) exported as `SIGSTORE_ID_TOKEN`
  in the sign step — recommended in-cluster. No credential to store.
- GitHub Actions OIDC (`id-token: write`) if you also run in Actions.

## What you do NOT need
- No Docker Hub credentials (nothing pushes there in this flow).
- No account passwords anywhere — only service-account tokens.
- No manually-stored GitHub token if you use `opc pac bootstrap` (the App flow).

## Summary: 4 credentials to obtain
1. **console.redhat.com** service account (user + token) — Lightwell jars
2. **registry.redhat.io** service account (user + token) — RHTAS/cosign images
3. **GitHub** repo admin — for `opc pac bootstrap`
4. **OpenShift** cluster-admin — for `oc`

(#5, the OIDC token, is minted at runtime — nothing to collect.)
